# SmartTrip UX Writing

為 SmartTrip mobile app 產生清楚、精簡、可操作的繁體中文介面文案。產品與 API 行為以 repo 的 `AGENTS.md`、`docs/DEVELOPMENT_SPEC.md` 和實際契約為準；文案不得補出尚未實作的能力或成功狀態。

## 語言與語氣

- 預設使用台灣繁體中文，技術欄位、API 名稱與程式識別字維持英文。
- 語氣冷靜、可靠、直接，像熟悉東京自由行的同行助手；不賣萌、不過度鼓舞，也不責怪使用者。
- 先說結果或目前狀態，再提供原因與下一步。
- 使用使用者熟悉的旅遊名詞，同一概念維持相同稱呼。
- 避免把英文的字數、閱讀年級或 sentence case 指標直接套用到中文；以 375–414px 螢幕上的可掃讀性與實際換行為準。

## 四個品質標準

每段文案都要同時符合：

1. **有目的**：協助使用者理解狀態或完成下一步。
2. **精簡**：刪除不影響理解的字，但不省略限制與風險。
3. **自然**：使用台灣使用者日常會說的句型，避免翻譯腔。
4. **清楚**：具體說明發生什麼事、影響範圍與可採取的行動。

## SmartTrip 不可違反的產品事實

- MVP 是單一 `demo-user`、`tokyo-demo` 單日行程；不要產生登入、多使用者、多日最佳化、正式訂位或取消功能的文案。
- `status: placeholder` 不是完成的重排。placeholder、fixture 與 fallback 必須明確標示，不能包裝成即時或正式結果。
- 未知天氣不能寫成晴天；未知費用、風險或影響不能寫成免費、零風險或沒有影響。
- 只有後端回傳 `status: ready` 且方案 `feasible: true` 時，才可提供「套用方案」操作。
- 不可行方案要說明不可套用及原因，不能只用顏色、圖示或「失敗」表示。
- 已完成、已預約或不可移動的活動限制必須可見；文案不能暗示系統已解除或變更預約。
- 偏好學習是依選擇更新權重，不是訓練 AI。套用成功前不要宣稱偏好已更新。
- Google Maps 是外部搜尋連結，不要寫成站內導航或已完成路線規劃。
- 不自行假設 API 尚未提供的原因、時間、費用或成功結果。

## Mobile 文案規則

- 每個畫面維持一個最重要的主要 CTA；次要操作降低語氣權重。
- 按鈕使用具體動作，例如「重新產生方案」、「查看地圖」、「套用方案」，避免只有「確定」、「送出」或「繼續」。
- 標題先呈現策略、推薦與可行性，再補異動、時間／費用與預約影響。
- 長地名、後端錯誤與方案說明必須允許換行；不要靠刻意縮寫隱藏必要資訊。
- loading 要描述正在進行的主要任務，並防止讓使用者誤以為需要再次點擊。
- error 要包含可恢復的下一步；若沒有可恢復操作，就如實說明目前無法繼續。
- 鎖定、推薦、錯誤、不可行與資料來源不能只靠顏色或 emoji 傳達。

## 常用模式

### 按鈕與連結

使用「動詞＋對象」，並讓標籤能單獨表達結果。

- 主要操作：「比較替代方案」、「套用方案」
- 重試：「重新載入行程」、「再試一次」
- 外部連結：「在 Google Maps 查看」
- 避免：「OK」、「Submit」、「點這裡」

### Loading

說明正在處理的工作，不保證尚未發生的結果。

- 「正在分析事件並比較替代方案⋯」
- 避免：「最佳行程即將完成」

### Error

依序交代「哪個動作未完成 → 已知原因或影響 → 下一步」。原因未知時不要猜測。

- 「無法載入目前行程。請檢查連線後再試一次。」
- 「方案尚未套用。請重新選擇後再試一次。」

### Empty 與不可行狀態

區分沒有資料、沒有符合條件的結果，以及存在但不可套用的方案。

- 空結果：「目前沒有可比較的替代方案。請調整事件描述後再試一次。」
- 不可行：「這個方案無法套用：會影響不可移動的預約行程。」

### 成功與偏好提示

只確認後端已完成的結果，並具體說明影響。

- 「已套用方案 B，行程時間已更新。」
- 「已記住你偏好較少移動的方案。」僅在後端確認權重已更新時使用。

## 工作方式

1. 先確認畫面階段、使用者剛完成的動作、後端實際狀態，以及下一個可用操作。
2. 先產生最短且不遺漏限制的版本，再檢查是否需要補上原因、資料來源或復原方式。
3. 若修改現有 UI，保持核心名詞一致，並同時檢查 loading、empty、error、disabled 與 success 狀態。
4. 文案涉及新功能、API 行為或產品承諾時，先指出契約缺口，不用文案掩蓋。
5. UI 變更後在 414px 與 375px 檢查換行、CTA 可見性、長文案及水平溢出。

## 按需載入的參考

普通文案直接依本檔處理，不要預先讀取所有參考資料。

- 無障礙或表單／錯誤 audit：讀取 `references/accessibility-guidelines.md`。
- 系統性檢查整頁或完整流程：讀取 `references/content-usability-checklist.md`。
- 需要更多 UI pattern 或語氣對照：讀取 `references/patterns-detailed.md`。
- 建立 SmartTrip voice chart：讀取 `references/voice-chart-template.md`。
- 撰寫複雜錯誤或空狀態：分別讀取 `templates/error-message-template.md` 或 `templates/empty-state-template.md`。
- 使用者要求 before/after 分析或評分方法：讀取 `examples/real-world-improvements.md`；只借用方法，不照搬電商、SaaS 或帳號情境。
